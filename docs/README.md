循证用药科普 RAG 智能Agent
基于 RAG 检索增强与多 Agent 协同的循证用药科普问答系统。仅使用公开合规资料（国家药监局公开说明书 + 权威慢病科普指南），通过「检索 → 科普解读 → 联用风险核验」三 Agent 协同，输出可溯源、带合规标注的用药科普回答。

定位：仅做药品科普与信息检索，不提供诊断、不替代医生药师。

背景与动机
通用大模型直接回答药品问题存在三大风险：

知识滞后：训练数据无法覆盖最新版说明书。
易幻觉：可能编造副作用、剂量、相互作用。
无出处：回答不可追溯，无法判断可信度。
本项目通过「私有合规知识库 + RAG 检索增强 + 多 Agent 职责隔离 + 防幻觉护栏」，把「可溯源、不编造」从一句提示词升级为系统级约束。

功能特性
药品科普问答：说明书信息检索、适应症 / 用法 / 不良反应 / 禁忌解读。
多药联用风险提示：≥2 种药品自动进入联用核验，输出三档风险分级。
防幻觉合规护栏：强制「文档 + 章节」出处标注；知识库无资料时固定兜底回复，禁止编造。
三档联用风险分级：明确禁止联用 / 需要谨慎联用 / 文档未记载相互作用。
高频问答缓存（设计）：Java(SpringBoot) + Redis 缓存层，布隆防穿透、锁防击穿、TTL 抖动防雪崩。

三个子 Agent 职责
Agent	职责	核心约束
检索 Agent	召回知识库原文片段	只搬运不创作，空结果固定回复
科普解读 Agent	专业文本通俗化转述	只转述不新增，分类标签（禁用/慎用/不良反应/用法/注意事项）
联用风险核验 Agent	多药交叉比对	只依据原文，三档分级，禁止脑补冲突
技术栈
检索增强（RAG）：结构化切分 + 父子 chunk + 向量/BM25 混合检索 + 别名归一化
多 Agent 协同编排：三 Agent 串行 + 条件路由
私有知识库治理：命名规范、章节结构化切片、10 字段元数据标签（section / drug_pair 等）
性能优化（预留）：Java(SpringBoot) + Redis 缓存层（穿透/击穿/雪崩三防）
知识库与合规声明
素材来源：仅公开免费合规资料——国家药监局公开药品说明书、权威慢病科普指南；不使用病历、隐私病例、内部临床资料。
合规红线：严禁疾病诊断、不替代医生药师、不给出诊疗方案；所有回答必须标注「仅科普参考，不构成医疗建议」。
防幻觉硬规则：每个结论标注「文档 + 章节」出处；知识库无对应信息时统一回复「暂无相关权威资料，无法解答」。

项目局限（诚实声明）
知识库规模有限，仅覆盖部分慢病常用药，冷门药 / 新药会查不到。
不做诊断与诊疗决策，联用风险仅提示知识库已记载的相互作用，「未记载 ≠ 安全」。
依赖公开资料版本，存在更新滞后，需注明「以最新版说明书为准」。
通俗转述存在信息损耗，因此每条保留「文档 + 章节」出处供回溯原文。
免责声明
本项目仅用于技术学习与简历展示，不构成任何医疗建议。实际用药请遵医嘱，并咨询执业医师或药师。
