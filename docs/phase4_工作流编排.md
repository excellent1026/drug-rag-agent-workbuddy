二、分支判断逻辑（决策规则）
判断输入：用户原文中出现的药品名称数量 N + 是否命中联用意图关键词。

条件	路由	说明
N ≥ 2	联用风险核验Agent	无论是否出现"一起吃"等词，只要出现≥2个药品名即核验
出现联用意图关键词（一起吃/同时服用/联用/合用/能一起吗/会不会冲突/搭配/混着吃）	联用风险核验Agent	命中即进联用分支
N = 1 且无联用意图	检索Agent → 科普解读Agent	单药科普
只问"XX能和别的药一起吃吗"但未列第二个药	走单药链路，解读Agent提示「请提供完整药品清单」	不臆断、不进入核验
分支判断要点：

药品名称抽取以「知识库药品名录 / 元数据 drug_name」为基准，命中才计数；口语别名需映射到通用名后再计数。
联用意图关键词的优先级高于药品数量：即使只识别到 1 个药，只要明确在问"能不能一起吃"，也进入联用分支（此时由核验Agent 提示补全清单）。
无法确定数量或意图时，默认走单药科普链路，宁可保守、不误判联用。

# 循证用药科普 RAG 工作流

你是本技能的编排器。严格按下述流程执行：

1. 解析用户输入：抽取药品名称数量 N + 判断联用意图关键词。
2. 分支路由：
   - 若 N≥2 或命中联用意图 → 调用【联用风险核验Agent】，透传其输出。
   - 否则 → 调用【检索Agent】召回原文，再把原文传给【科普解读Agent】，透传其输出。
3. 只透传、不脑补，禁止自己替代任何子Agent。
4. 最终回答必须保留子Agent 自带的 ⚠️ 免责声明。
六、在 WorkBuddy 里设置自动流转触发条件
方式 A：用「Skill（技能）」承载工作流（推荐）
新建技能，粘贴上面的 SKILL.md（或我交付的完整模板）。
触发条件写在 frontmatter 的 description 里：把「触发词」写全（用药、副作用、不良反应、禁忌、联用、一起吃、能一起吗、会不会冲突……），用户输入命中任意触发词即自动调用该技能。
技能的正文（body）放「流程控制提示词」，让主控按分支逻辑串行调度三个子Agent。
方式 B：用「主编排Agent」承载工作流
新建一个 Agent，把第三节「流程控制提示词」作为它的系统提示词。
在 Agent 配置里，把三个子Agent 声明为可调用的子Agent（检索Agent / 科普解读Agent / 联用风险核验Agent）。
触发条件：让用户 @该编排Agent，或在对话设置里把它设为「用药类问题」的默认路由 Agent。
关键配置点（两种方式通用）
触发词：决定"什么时候自动启动工作流"（写在 description 或 Agent 的触发条件里）。
子Agent 调用关系：决定"串行流转"——主控提示词里必须显式写「检索Agent → 科普解读Agent」「药品清单 → 核验Agent」。
变量透传：确保原文片段原样传给解读Agent、药品清单原样传给核验Agent，中间不加工。
说明：不同 WorkBuddy 版本的按钮位置/名称可能略有差异，但核心就这三点——触发词、子Agent 调用关系、变量透传。若你的版本支持「多Agent 工作流可视化编排」，可直接把上面流程图拖成串行 + 条件分支节点。
