二、简历项目描述完整版
项目名称
循证用药科普 RAG 智能Agent

项目概述
通用大模型直接回答药品问题存在「知识滞后、易幻觉、无出处」三大风险，无法用于医疗科普场景。本项目构建一个面向公众的循证用药科普问答系统，仅使用公开合规资料（国家药监局说明书 + 权威慢病指南），通过「检索 → 科普解读 → 联用风险核验」三 Agent 协同，输出可溯源、带合规标注的回答。

主要工作（简历 bullet，按技术栈分层）
私有知识库治理：制定文档收集与命名规范，实现说明书「按章节标题结构化切分 + 父子 chunk」，构建 10 字段元数据标签体系（doc_type / drug_name / section / drug_pair 等），支撑检索 Agent 按章节精准过滤。
RAG 检索增强：采用「结构化切分 + 向量/BM25 混合检索 + 药品别名归一化」方案，针对说明书长文本减少漏召回，召回 top_k=5~8。
多 Agent 协同编排：设计检索 Agent（忠实召回原文）、科普解读 Agent（通俗转述 + 分类标签）、联用风险核验 Agent（多药交叉比对 + 三档风险分级）三个子 Agent，通过条件路由（药品数 ≥2 自动分流到核验 Agent）实现串行编排。
防幻觉合规护栏：强制「文档 + 章节」出处标注、空结果固定兜底、禁止编造，使每个结论可回溯原文，解决大模型医疗应用的幻觉痛点。
性能优化（预留/设计）：设计 Java(SpringBoot) + Redis 高频问答缓存层——布隆过滤器防穿透、分布式锁防击穿、TTL 随机抖动防雪崩，降低重复 LLM 调用成本与响应延迟。
项目成果（量化，占位可填）
知识库覆盖 XX 种慢病常用药 + XX 份权威指南；设计 XX 条测试用例，覆盖单药查询、禁忌、联用、防幻觉、不良反应五类场景全部通过。
高频问答经缓存层命中后，平均响应延迟由 XXms 降至 XXms，重复 LLM 调用成本下降 XX%。
无数据时的保守写法（应届生可用，诚实不吹）
将「命中率/延迟」类结果改为过程性表述，如：
「针对说明书长文本优化检索策略，对比固定长度切分，漏召回问题明显改善；并通过缓存层设计，将高频问答的重复推理开销收敛为一次缓存命中。」

三、项目创新点（3 条，面试口述用）
创新点 1：面向医疗场景的「防幻觉合规护栏」
一句话：把「可溯源、不编造」从一句 Prompt 提示，升级为系统级约束。
口述展开：我没有让一个大模型直接回答药品问题，而是把职责拆成三个 Agent 各管一段——检索 Agent 只负责忠实搬运原文、解读 Agent 只负责转述不新增、核验 Agent 只基于原文交叉比对。同时强制每个结论标注「文档 + 章节」出处，知识库查不到就固定回「暂无相关权威资料」。这样幻觉不是靠"提醒"避免，而是靠架构隔离 + 强制格式从机制上杜绝。
创新点 2：针对药品说明书长文本的检索增强优化
一句话：说明书是强结构化长文本，通用 RAG 的固定长度切片会切断语义，我做了针对性优化。
口述展开：说明书的「禁忌」「不良反应」是独立章节，固定 600 字硬切会把一条禁忌拦腰切断导致漏召回。我的方案是「按章节标题结构化切分 + 父子 chunk（小块检索、整章返回）+ 向量/BM25 混合检索 + 商品名→通用名归一化」，四件套专门解决长文本的语义完整性和同义词召回盲区。
创新点 3：多 Agent 条件路由编排 + 可扩展缓存设计
一句话：从"AI 能力"延伸到"工程化落地的完整思维"。
口述展开：入口做了条件路由——用户一次提到 ≥2 种药就自动分流到联用核验 Agent，单药走检索→解读链路，边界情况（只问"能不能和别的药吃"但没列药名）会保守地提示补全而不是臆断。同时预留了 Java(SpringBoot) + Redis 缓存层，用布隆过滤器防穿透、分布式锁防击穿、TTL 抖动防雪崩，体现我把 AI 应用当成可上线系统来设计，而不只是一个 demo。
